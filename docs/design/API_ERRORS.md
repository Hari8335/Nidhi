# Nidhi v1 Standard API Error Model

This document defines the error handling protocol, HTTP status code semantics, RFC 7807/9457 Problem Details response envelope, and stable application error codes for Nidhi v1. It implements the requirements in [OPEN_DECISIONS.md](../requirements/OPEN_DECISIONS.md) and [NON_FUNCTIONAL_REQUIREMENTS.md](../requirements/NON_FUNCTIONAL_REQUIREMENTS.md) (NFR-SEC-004).

---

## 1. Error Response Envelope: RFC 7807 / RFC 9457 Problem Details

All error responses from the Nidhi ASP.NET Core API return `Content-Type: application/problem+json`.

```json
{
  "type": "https://api.nidhi.lk/errors/PRICE_CHANGED",
  "title": "Simulated gold price has changed",
  "status": 409,
  "detail": "The submitted price version '018f3a5b-...' is no longer current. The latest price is LKR 31,500.0000 per gram.",
  "instance": "/api/v1/customer/gold-purchases",
  "code": "PRICE_CHANGED",
  "timestampUtc": "2026-09-24T08:15:00.123Z",
  "traceId": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",
  "errors": {}
}
```

### Fields Specification
- `type`: URI identifying the error problem type.
- `title`: Short, human-readable summary of the problem type.
- `status`: The HTTP status code generated by the origin server.
- `detail`: Human-readable explanation specific to this occurrence of the problem. Must **never** leak database stack traces, SQL syntax, or internal credentials (NFR-SEC-004).
- `instance`: The URI reference of the endpoint that originated the error.
- `code`: Stable, enumerated machine-readable application error code.
- `timestampUtc`: UTC timestamp when the error occurred.
- `traceId`: W3C distributed trace identifier for log correlation and operational troubleshooting (NFR-OBS-001).
- `errors`: Optional dictionary of field-level validation errors (used exclusively with `VALIDATION_ERROR`).

## 2. Stable Application Error Codes

To eliminate ambiguity across client implementations and automated testing, Nidhi defines a curated set of stable error codes.

### 2.1. Authentication & Authorization Errors

| HTTP Status | Application Error Code | Meaning / Trigger Scenario |
|---|---|---|
| `401 Unauthorized` | `AUTHENTICATION_REQUIRED` | Request requires an authenticated session cookie, but no valid session was provided. |
| `401 Unauthorized` | `INVALID_CREDENTIALS` | Login attempt failed due to invalid email or password. Does not disclose whether email exists. |
| `403 Forbidden` | `FORBIDDEN` | Authenticated caller does not have permission (e.g., Customer invoking an Admin endpoint). |
| `403 Forbidden` | `EMAIL_NOT_VERIFIED` | Customer has registered but has not yet verified their email. Simulated financial features are blocked until verification (OD-002). |

---

### 2.2. Validation & Resource Errors

| HTTP Status | Application Error Code | Meaning / Trigger Scenario |
|---|---|---|
| `400 Bad Request` | `VALIDATION_ERROR` | Request body or parameters failed syntax/range/format rules. `errors` field contains field-level messages. |
| `400 Bad Request` | `INVALID_TOKEN` | Password reset or email verification token is malformed, invalid, or expired. |
| `404 Not Found` | `RESOURCE_NOT_FOUND` | Requested entity (e.g., customer, transaction) does not exist or caller does not own it. |
| `409 Conflict` | `EMAIL_ALREADY_EXISTS` | Registration attempt with an email that is already registered. |
| `409 Conflict` | `ACTIVE_GOAL_ALREADY_EXISTS`| Attempt to create an active goal when an active goal already exists (and replace was not specified). |

---

### 2.3. Financial & Simulation Errors

| HTTP Status | Application Error Code | Meaning / Trigger Scenario |
|---|---|---|
| `422 Unprocessable` | `INSUFFICIENT_SIMULATED_FUNDS` | Gold purchase amount exceeds customer's available wallet balance (`amountLkr > wallet.BalanceLkr`). |
| `422 Unprocessable` | `WALLET_LIMIT_EXCEEDED` | Funding operation would cause wallet balance to exceed LKR 5,000,000.00 (OD-003). |
| `422 Unprocessable` | `DAILY_FUNDING_LIMIT_EXCEEDED` | Customer has already completed 20 successful funding operations in the current UTC calendar day (OD-003). |
| `422 Unprocessable` | `GOLD_AMOUNT_OUT_OF_RANGE` | Gold purchase amount is `< 100.00` or `> 1,000,000.00` LKR, or has more than 2 decimal places (OD-004). |
| `422 Unprocessable` | `GOLD_QUANTITY_ZERO` | After rounding down to 8 decimal places, the calculated gold grams are `0.00000000` (OD-005). |

---

### 2.4. Price Freshness & Publication Errors

A critical architectural distinction is made between the three price error states (OD-006, OD-017):

| HTTP Status | Application Error Code | Semantic Distinction |
|---|---|---|
| `409 Conflict` | **`PRICE_CHANGED`** | **The customer submitted a valid, previously active price version, but a newer price version was published before execution.** Rejection requires the customer to review the new price and reconfirm. Silent substitution of the new price is strictly prohibited. |
| `503 Service Unavailable` | **`PRICE_STALE`** | **The active price version exists, but its publication timestamp is older than 24 hours.** The pricing service is temporarily unavailable for executing purchases until an Administrator publishes an updated price. |
| `503 Service Unavailable` | **`PRICE_UNAVAILABLE`** | **No usable published price version currently exists in the system.** Occurs in production before an Administrator publishes the very first price version (OD-017). Purchases and quotes are unavailable. |

---

### 2.5. Idempotency & Concurrency Errors

| HTTP Status | Application Error Code | Meaning / Trigger Scenario |
|---|---|---|
| `409 Conflict` | `IDEMPOTENCY_CONFLICT` | The supplied `Idempotency-Key` was previously used for this operation with a **different request payload** (OD-012). |
| `409 Conflict` | `OPERATION_IN_PROGRESS` | A request with the same `Idempotency-Key` is currently executing concurrently. Client should retry after a short delay. |

## 3. Validation Error Response Example

```json
{
  "type": "https://api.nidhi.lk/errors/VALIDATION_ERROR",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "detail": "The request payload failed input validation rules.",
  "instance": "/api/v1/customer/wallet/fundings",
  "code": "VALIDATION_ERROR",
  "timestampUtc": "2026-09-24T08:00:00.000Z",
  "traceId": "00-1234567890abcdef-1234567890abcdef-01",
  "errors": {
    "amountLkr": [
      "Amount must be between 100.00 and 1,000,000.00 LKR.",
      "Amount cannot have more than 2 decimal places."
    ]
  }
}
```

## 4. Price Changed Conflict Response Example

When a customer attempts to save gold using a price that has been superseded:

```json
{
  "type": "https://api.nidhi.lk/errors/PRICE_CHANGED",
  "title": "Simulated gold price has changed",
  "status": 409,
  "detail": "The price version submitted (018f3a5b-...) is no longer current. Please reconfirm your purchase with the updated price.",
  "instance": "/api/v1/customer/gold-purchases",
  "code": "PRICE_CHANGED",
  "timestampUtc": "2026-09-24T08:15:00.000Z",
  "traceId": "00-abcdef1234567890-abcdef1234567890-01",
  "activePrice": {
    "priceVersionId": "018f3a5b-7c2a-7182-9a3b-8c4d5e6f7a94",
    "pricePerGramLkr": 31500.0000,
    "publishedAtUtc": "2026-09-24T08:14:58.000Z"
  }
}
```
The client UI uses the `activePrice` object to prompt the customer with the new price quote and ask for explicit reconfirmation with a new idempotency key.
